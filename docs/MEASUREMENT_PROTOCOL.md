# 모델 검증용 자료 준비

현재 앱의 kWh 차이는 **모델 출력**입니다. 실측으로 절감률을 주장하려면 기준 곡선과 후보 곡선의 **동일 운행 조건**을 각각 계측해야 합니다. 이 문서는 자료 형식과 비교 순서를 정의하며, 측정값이나 시험 결과를 대신하지 않습니다.

## 필요한 자료

1. 두 운행의 조건표: 카 자중, 정격 적재와 실제 적재(kg), 균형추(kg), 로프·회전체 환산 질량(kg), 상/하행, 출발/도착층, 실제 이동거리(m), 기준·후보 제어곡선의 설정, 운행 시작·종료 시각. 운행마다 동일한 조건인지 확인하고 다르면 따로 기록합니다.
2. 기준·후보 각각의 동기화된 `time_s,speed_m_s,grid_kw` CSV. 첫 표본은 운행 시작 후 0.2초 이내이고, 마지막 표본은 운행 끝까지 포함합니다. `grid_kw`는 계통에서 소비할 때 양수, 계통으로 회수할 때 음수입니다. 측정 위치와 회생 전력의 계통 반환 여부를 함께 기록합니다. 개인 정보는 제거합니다.
3. 별도 기계·열 검증에는 모터축 토크·속도·효율 운전점 자료, 제동 저항기 전압/전류 및 정격(펄스·평균·반복주기), 모터 허용 피크 및 연속 토크, 브레이크 시험 기록이 필요합니다. 현재 CSV 세 열만으로는 이를 검증할 수 없습니다.

CSV 예시(수치는 **형식 설명용 가상값**):

```csv
time_s,speed_m_s,grid_kw
0,0,0.15
0.1,0.01,0.32
0.2,0.04,0.58
```

## 검증 절차

1. 원본 파일·측정기 모델·샘플 간격·시계 동기화·전력 계측 위치를 기록하고 사본으로 계산합니다.
2. 기준과 후보 각각의 실측 속도 곡선을 모델과 비교합니다. 앱의 `speed_rmse_m_s`와 운행시간 차이를 확인합니다.
3. 전력 표본을 시간에 대해 적분한 kWh와 예측 순 kWh를 비교합니다. 현재 `read_measurement`는 사다리꼴 적분과 상대 오차를 반환합니다. CSV가 운행 중 전력만 포함하면 정지·대기 보조 전력을 포함하는 청구서 kWh와 직접 비교할 수 없습니다.
4. 같은 적재·거리·방향의 여러 운행을 반복해 운행별 잔차를 기록합니다. 적재와 방향별로 나눠 검토한 뒤에만 두 곡선의 실측 차이를 보고합니다. 측정 불확도·반복 간 분산·유휴 전력 경계를 함께 제시합니다.

Windows에서 앱을 직접 실행할 때는 여섯 탭의 입력→Enter 계산→Tab 이동, 프로젝트 저장/재불러오기, PNG 저장/열기, 오류 CSV의 안내 메시지를 확인하고 Windows 버전·실행 파일 빌드 번호·결과 화면을 기록합니다. CI의 실행 파일 빌드는 이 사용자 화면 시험을 대신하지 않습니다.
