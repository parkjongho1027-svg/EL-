# 설계 검증 및 제품화 작업 목록

실제 완료 상태는 README와 테스트 결과를 우선합니다. 현재 실측 운행 자료를 확보할 수 없으므로 3주차의 **실측 오차·절감률 검증은 보류**합니다. 합성 데이터 및 물리적 보존 법칙 검사는 소프트웨어 내부 일관성 확인이며, 실측 오차로 표시하지 않습니다. 아래 일부 항목은 추후 제조사·검사기관 자료를 확보해야 실행할 수 있습니다.

## 1주차 — 남은 UI 분리

1. `main.py`에 남아 있는 여섯 화면을 `src/ui`의 패널별 모듈로 이동하고 실행 진입점만 남깁니다. 기존 프로젝트 저장 형식과 Tab·Enter 동작을 그대로 유지하는 회귀 검사를 실행합니다.
2. `storage.py`, 그래프 렌더러와 사용자 설정 로딩을 UI 어댑터로 구분합니다. `src/core`에서 Tk·저장경로·전역 설정을 import하지 않는지 정적 검사를 유지합니다.
3. 현재 버튼 실행과 PNG 생성은 메인 스레드에서 수행합니다. 장시간 연산의 취소·결과 순서·진행 표시가 필요하면 동일한 작업 큐와 샘플 상한을 적용합니다.

## 2주차 — 기준값의 출처와 오차

1. KC 2050-51:2022 해당 조항의 **입력·계산값·적용 조건**을 공식 원문과 대조한 표를 만듭니다. 공개 KOEL 자료나 사용권이 있는 교재의 예제 원문에서 20~30건을 확보하기 전에는 공인 예제로 표시하지 않습니다.
2. 예제마다 출처 식별자·쪽수·단위·입력·기대값·반올림 규칙·적용 범위를 함께 저장하고, 별도 pytest 파라미터로 수치 오차를 확인합니다. 산술 오차 `0.001%`는 측정 정밀도 또는 법정 적합성과 구분합니다.
3. 회생 구간, 등가 관성, 적재 초과, 짧은 운전주기, 영속도와 잘못된 파일 형식을 엣지 케이스로 검사합니다. 제조사 허용 피크 토크, 연속 토크, 저항기 펄스·연속 전력 및 제동 횟수 자료와 비교할 검증 필드를 정의합니다.

## 3주차 — 모델과 데이터

1. 실제 속도·전력·토크 및 브레이크 저항기 전압/전류 로그를 같은 운행 조건에서 수집합니다. 이동방향, 적재, 층수별 5분 수송 인원의 실측/배차 로그를 별도로 모읍니다.
2. 기동·주행·제동 구간의 잔차와 운행별 kWh, RMS 토크, 저항기 에너지의 오차를 계산하고 구간별 가정을 교정합니다. 실측 근거가 없으면 '절감형' 또는 '검증 완료'로 표시하지 않습니다.
3. 그래프의 장력은 현재 정적 근사이고 교통량은 균등 목적층 모형입니다. 제조사 로핑·보상 및 도어/배차/승객 도착 모델을 별도 입력으로 확장하고 그래프에 가정과 버전을 표시합니다.

## 4주차 — 빌드와 설명

1. GitHub Actions의 Ubuntu Python 3.12·3.14 테스트와 Windows 3.14 빌드 성공 및 Windows 실제 실행을 확인합니다. 서명·배포 절차는 별도 승인 후 결정합니다.
2. `pytest-cov`로 **실제** `src/core` 분기/줄 커버리지를 측정하고 부족한 계산 경로를 보강합니다. 현재 Python 3.12에서 181개 pytest 통과, **`src/core`만** 대상으로 한 합산 커버리지 91.30%이며 CI와 로컬 훅의 최소 하한은 90%입니다. UI·저장소 커버리지는 포함되지 않습니다.
3. 실제 v69 실행 화면과 시연 GIF를 Windows에서 촬영해 구 버전의 화면 예시를 교체합니다. KC 조항과 EN 규격의 법적 인용 범위를 전문가 검토한 뒤 문서에 적용 여부를 기재합니다.
